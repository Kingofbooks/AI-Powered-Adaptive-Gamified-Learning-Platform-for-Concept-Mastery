## 🎯 First Week with the Software

### Day 1: Introduction (20 minutes)

**Your Goals:**
- Get comfortable with the interface
- Create your first simulation
- Understand basic controls

**What to Do:**

1. **Launch the program** (5 min)
   ```bash
   ./EduSandbox
   ```
   - Familiarize yourself with the window
   - Identify: simulation area, toolbar, prompt box
   - Notice the grid background

2. **Create your first objects** (5 min)
   - Click "Ball" button → See it fall
   - Click "Ground" button → See it bounce
   - Practice clicking and dragging objects

3. **Try keyboard controls** (5 min)
   - Press `P` to pause
   - Press `P` again to resume
   - Press `+` to speed up
   - Press `-` to slow down
   - Press `R` to reset

4. **Try a command** (5 min)
   - Click the text box (or press Enter)
   - Type: `create red ball at top`
   - Press Enter
   - Watch it appear!

**Success Criteria:**
✓ Can create objects with buttons
✓ Can drag objects around
✓ Can pause and resume
✓ Can type and execute one command

---

### Day 2: Building Confidence (30 minutes)

**Your Goals:**
- Practice creating complex scenes
- Learn explanation commands
- Experiment freely

**Activities:**

1. **Morning Practice** (10 min)
   ```
   create ground at bottom
   create red ball at 200 100
   create blue ball at 600 100
   create yellow ball at 400 50
   ```
   - Watch all three balls fall
   - Pause mid-fall
   - Type: `explain gravity`

2. **Afternoon Practice** (10 min)
   ```
   clear
   create ground at bottom
   create ramp at 200 350
   create ball at 150 300
   ```
   - Watch ball roll down ramp
   - Drag ball back to top
   - Try different positions

3. **Experimentation** (10 min)
   - Try different colors
   - Try different positions
   - Create your own scenes
   - Press `H` for help when needed

---

### Day 3: Lesson Planning (45 minutes)

**Your Goals:**
- Plan first student lesson
- Prepare questions and activities
- Practice narration

**Steps:**

1. **Choose a Topic** (10 min)
   - Start simple: "Introduction to Gravity"
   - Write learning objective
   - List key concepts

2. **Create the Demonstration** (15 min)
   - Write out commands you'll use
   - Practice running them
   - Note where you'll pause
   - Prepare questions to ask

3. **Practice Narration** (20 min)
   - Run simulation while talking
   - Explain what's happening
   - Ask questions out loud
   - Time yourself

**Sample Script:**
```
"Today we're learning about gravity. Watch what happens 
when I create a ball at the top of the screen."

[Click Ball button]

"Notice it's falling. Is it speeding up or staying the same speed?"

[Pause simulation]

"Let's find out. I'll ask the computer to explain gravity."

[Type: explain gravity]

"See? It accelerates at 400 pixels per second squared..."
```

---

### Day 4: First Student Lesson (40 minutes)

**Setup:**
- Computer connected to projector
- Students can see clearly
- You have notes ready

**Lesson Flow:**

1. **Hook** (5 min)
   - "What happens when I drop my keys?"
   - Launch program
   - Create ball

2. **Explore** (15 min)
   - Create multiple objects
   - Students suggest positions
   - You type their ideas
   - Discuss results

3. **Explain** (10 min)
   - Use `explain gravity`
   - Draw on whiteboard
   - Connect to real world

4. **Apply** (10 min)
   - Students predict new scenarios
   - Test predictions
   - Discuss accuracy

---

### Day 5: Reflection and Planning (30 minutes)

**Reflect:**
- What went well?
- What confused students?
- What would you change?

**Plan Ahead:**
- Next week's topics
- More complex simulations
- Student hands-on time

## 👥 Classroom Management

### Whole-Class Demonstrations

**Setup:**
- Teacher computer + projector
- All students can see
- Classroom fairly quiet

**Best Practices:**
1. **Start with attention-getter**
   - "Watch this ball carefully!"
   - Create dramatic scenario
   
2. **Narrate constantly**
   - Don't let silence happen
   - Explain what's happening
   - Ask questions
   
3. **Pause frequently**
   - Stop at key moments
   - Give thinking time
   - Check understanding

4. **Invite participation**
   - "Where should I put this?"
   - "What color should we use?"
   - "What do you think will happen?"

---

### Small Group Rotations

**Setup:**
- 1-2 computers in classroom
- Students rotate through
- 10-15 min per group

**Station Instructions:**

**Group 1: Exploration**
- Free play with the software
- Try different commands
- Create interesting scenarios

**Group 2: Guided Challenge**
- "Make the ball bounce 5 times"
- "Create a marble run"
- Worksheet with objectives

**Group 3: Assessment**
- Demonstrate a concept
- Explain what's happening
- Teacher observes

**Group 4: Other activity**
- Reading, worksheet, etc.
- While waiting for computer

---

### Computer Lab Sessions

**Setup:**
- Each student (or pair) has computer
- Software installed on all machines
- Teacher can see all screens

**Structure:**

1. **Introduction** (10 min)
   - Demonstrate on projector
   - Show today's objective
   - Give clear instructions

2. **Guided Practice** (15 min)
   - Everyone does same activity
   - Teacher circulates
   - Help struggling students

3. **Independent Exploration** (15 min)
   - Students try their ideas
   - Teacher monitors
   - Answer questions

4. **Sharing** (10 min)
   - 2-3 students show work
   - Class discusses
   - Teacher reinforces concepts

## 🎨 Differentiation Strategies

### For Struggling Students

**Simplify:**
- Start with just buttons (no commands)
- One object at a time
- Very structured steps

**Support:**
- Printed command cards
- Step-by-step worksheets
- Partner with stronger student

**Example Activity:**
```
Step 1: Click "Ground" button
Step 2: Click "Ball" button
Step 3: Watch what happens
Step 4: Draw what you see
```

---

### For Advanced Students

**Challenge:**
- Complex scenarios
- Multiple objects
- Prediction and calculation

**Extensions:**
- "Can you make the ball bounce exactly 3 times?"
- "Create a marble run with 4 ramps"
- "Calculate the final velocity"

**Example Activity:**
```
Challenge: Build a Rube Goldberg machine
- Must use at least 5 objects
- Ball must change direction twice
- Must take at least 5 seconds
```

---

### For English Language Learners

**Visual Focus:**
- More demonstration, less explanation
- Use drawings and diagrams
- Command cards with pictures

**Language Support:**
- Simplified vocabulary
- Sentence frames
- Partner with fluent speaker

**Example:**
```
"The ball _____ down."
"Gravity pulls objects _____."
"When objects hit, they _____."
```

---

### For Students with IEPs

**Accommodations:**
- Extended time
- Simplified instructions
- Alternative assessments
- Assistive technology

**Modifications:**
- Fewer objects to manage
- Pre-created scenarios
- Focus on observation vs. creation

## 📊 Assessment Tools

### Formative Assessment

**During Demonstrations:**

1. **Thumbs Up/Down**
   - "Thumbs up if you think it will bounce"
   - Quick check of understanding

2. **Turn and Talk**
   - Pause simulation
   - "Tell your partner why"
   - Listen to conversations

3. **Whiteboard Responses**
   - "Draw the path you think it will take"
   - Hold up for teacher to see

4. **Quick Polls**
   - "How many think red will hit first?"
   - Count hands, discuss

---

### Exit Tickets

**3-2-1 Format:**
- 3 things you learned
- 2 questions you have
- 1 way you'll use this

**Prediction Format:**
```

2. Why?
3. Draw the motion path.
```

- Draw a simulation setup
- Label forces

## 🔧 Troubleshooting Common Issues

### Technical Problems

**"Program won't start"**
```bash
# Check SDL2 installation
sdl2-config --version

# Reinstall if needed
sudo apt-get install libsdl2-dev libsdl2-ttf-dev
```

**"Text doesn't show"**
- Font file missing
- Program works without text
- Edit main.cpp to point to your font

**"Objects fall through ground"**
- Ground must be below objects
- Use: `create ground at bottom`
- Or drag ground down

**"Simulation runs slow"**
- Close other programs
- Reduce number of objects
- Older computers may struggle

---

### Student Misconceptions

**"I can't type anything"**
- Click the text box first
- Or press Enter
- Look for cursor

**"Nothing happens when I type"**
- Did you press Enter?
- Check spelling
- Try clicking a button instead

**"My ball disappeared"**
- It fell off screen
- Add ground first
- Press R to reset

**"It's not working!"**
- Press H for help
- Check the example commands
- Ask teacher
